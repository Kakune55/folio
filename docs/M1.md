# M1 实施记录

2026-10-15。**M1 退出条件已通过验收。** 已完成认证/条件保存、附件、文件操作与单容器部署四个节点。amd64 原生运行、arm64 QEMU 用户态仿真均通过容器流程；不等于所有 M3 质量检查已完成。

## 节点一：认证、真实目录与条件保存

- Go 服务连接独立的工作区和应用数据目录；两者不能相互包含。普通文件是正文唯一权威，SQLite 只保存 Argon2id 账号数据及已哈希会话令牌。
- 单用户账号 `admin`。首次启动读取 `FOLIO_PASSWORD_FILE`，或生成应用数据目录中的私密 `initial-password` 文件；不输出密码到日志。初始化密码不少于 12 字节。记录密码后可删除生成的明文引导文件；既有账号继续使用数据库中的哈希。
- 会话有效期 7 天，持久化到 SQLite；重新登录轮换当前 Cookie 对应的会话，退出撤销会话。Cookie 为 HttpOnly、SameSite=Strict，默认 Secure。登录限速按连接源 IP 执行，不信任客户端转发头；反向代理后可能共享限速桶。
- 所有文件接口要求会话，修改要求 CSRF 和来源校验。API 均 `no-store`，错误不包含服务端绝对路径。
- 真实文件夹列表、新建目录、新建文本文件、Markdown/文本读取、800ms 自动保存、显式保存、关闭标签页前保存、草稿下载。
- 同一路径的保存请求串行。请求中继续编辑保持 dirty，成功响应只确认已发送快照，后续修改使用新的 ETag 保存。
- 冲突停止自动重试，保留本地草稿，支持比较磁盘版本、下载本地草稿，以及“将本地草稿保存为副本并加载磁盘版本”。不提供隐式强制覆盖。
- 登录过期时不清空编辑会话；重新登录可重试保存。保存失败保留脏标签页，不假装关闭成功。
- 正式入口没有内置示例。M0 回归演示移到开发环境 `/?demo=1`，生产构建不提供此入口。

## 节点二：附件与查看器

- 流式上传至当前选择目录；一请求一文件，批量选择时逐个上传并分别报告结果。文件名与路径校验、大小上限及同名不覆盖由服务端执行，不依赖 Content-Length。畸形多文件请求、超限或类型不符合图片粘贴要求时，不提交目标文件。
- 新增文件元数据与编辑器/查看器注册表。Markdown、已识别 UTF-8 文本、常见图片、PDF 与未知二进制分别分发。源码高亮按文件名异步加载，失败保留纯文本并明确提示。
- PNG/JPEG/GIF/WebP 使用内容嗅探和图像头验证后才允许预览；默认限制 20 MiB、3200 万像素。SVG/HTML 只显示源码或下载。未知附件原样下载，不提取压缩包、不执行文件。
- PDF 默认限制 50 MiB，通过动态加载的 PDF.js 6.4.299 与同源 worker 渲染到 canvas，提供分页与原文件下载。没有创建注释/表单 HTML 层或执行 PDF 动作；关闭 XFA 与 WASM、限制画布和图片像素。未额外分发字体文件。
- 所有下载/预览均要求会话，下载强制 `application/octet-stream` + attachment；预览仅开放位图/PDF白名单，添加 nosniff、same-origin CORP 与 sandbox CSP。PDF.js 只读取预览响应的二进制。
- Markdown 富文本与源码模式均支持粘贴/拖放本地图片，上传成功后插入普通相对路径，不把 API URL 写入 Markdown。富文本显示时才将相对路径映射为认证预览地址。
- 图片上传期间继续输入时，插入位置随文档事务映射。切换文件或模式后，完成的图片链接追加到原笔记并触发条件保存；上传中的会话不能被关闭/退出抛弃。临时 blob 地址不进入文件。
- 标准相对文件链接在应用标签页打开；外部 HTTP(S) 使用独立窗口及 noopener/noreferrer。拒绝活动协议与上溢路径。外部图片默认不联网加载，正文中的原始地址仍保留；段内锚点跳转暂不支持。

## 节点三：文件操作与回收站

- 文件和目录支持行内重命名（Enter 提交、Escape 取消）、菜单移动和移到回收站。省略号菜单在鼠标悬停/键盘焦点时可见，移动端保持可见，并提供右键入口。移动使用完整工作区相对目标路径，不自动重写 Markdown 链接。
- 文件操作前锁定受影响会话，清空待触发的自动保存计时器，等待正在进行的保存并确认已打开文件的内容版本。原路径与目标路径均被保留，禁止其他异步打开结果抢占目标会话。操作中不接受新的图片粘贴。
- 移动成功后，文件/目录下的会话路径、标签页、当前导航、附件预览地址一起更新；继续编辑会使用新路径和原内容 ETag。重命名改变文件类型时重新分类，只有先读取到正文和版本后才从只读查看器转成文本编辑器。
- 删除需要确认，先保存已打开的修改。成功进入回收站后关闭对应的干净标签页。遇到冲突、网络中断或持久性不确定错误时保留缓冲区，不能假装保存或关闭成功。
- `internal/trash` 以普通 JSON 清单和普通文件 payload 记录原始路径、内容摘要、类型、时间和状态。SQLite 不保存回收正文。清单原子替换并同步，损坏条目在 UI 中明确保留，不自动丢弃。
- 文件/目录操作都需要 `If-Match`。目录版本由排序后的完整子树文件名、节点类型、目录权限和文件内容摘要生成。含符号链接、特殊文件或未完成临时条目的子树会明确拒绝操作。
- 同盘回收优先同步原文件后原子移至回收站。跨文件系统回收先在原父目录下用保留名称隔离原件，再复制到应用数据卷并核对摘要/同步，写好 ready 清单，最后清理隔离原件。不能将跨盘复制伪称为原子 rename。
- 恢复总是拒绝覆盖已有路径。跨盘恢复在目标父目录的独占临时容器内构建完整副本，核对并同步后才原子发布。恢复只清理本次创建的临时数据，不能清理其他故障留下的版本。

## 文件安全与一致性边界

仅支持 Linux 5.6+ 的 `openat2`，并需要可用的 `/proc/self/fd`。缺失安全原语时明确失败，不降级为字符串前缀检查。以根目录描述符解析路径，拒绝路径穿越、符号链接、跨挂载点、设备/FIFO/套接字及多硬链接普通文件。先以 O_PATH 检查 inode，再通过已验证的描述符打开内容，避免检查类型前访问设备。

目前单实例内对存储操作加互斥锁，同目录创建私密临时文件，完整写入、设置权限、同步文件，然后在紧邻替换前重新读取当前内容哈希并复核父目录身份。创建使用 `RENAME_NOREPLACE`，更新原子替换后同步父目录。目录同步失败返回明确的持久性不确定错误，客户端保留草稿。

**边界**：外部工具不遵守应用锁；最终校验与 rename 之间仍存在不可由普通文件 API 消除的极短竞争窗口。当前实现检测最终校验之前的外部修改，不宣称对任意恶意外部并发写入实现文件系统 CAS。部署应只有一个 Folio 实例，避免外部工具与页面同时写同一文件；后续外部变更检测不能代替条件保存。目录描述符遵循 inode 身份；本地特权进程仍能移动目录、改挂载或修改应用数据，不在远程 API 的信任边界内。

目前应用数据目录持有独占锁，但不能阻止两个不同应用数据目录配置为同一工作区。部署必须保证工作区仅有一个实例。

## 当前限制

- 基础重命名、移动、回收站与容器验收已完成；拖拽移动、快开、搜索与外部变更提示按 M2 推进。文本工具栏导出当前草稿，附件工具栏下载磁盘原文件。
- 没有持久化浏览器恢复缓存；刷新前未成功保存的草稿仍有丢失风险，离开确认只作辅助。断网后保留内存草稿，提供显式重试；未实现后台有界重试。
- 文件或模式切换保留正文，撤销历史和光标仍重置。中文原生输入法、移动端键盘和屏幕阅读器尚未完整验收。
- 单页目录默认 200 条，最多 1000 条，支持加载更多；分页不提供外部变动下的一致快照。服务端当前仍读取目录元数据后排序，超大目录性能待 M3 实测。
- 文本默认上限 5 MiB，只接受无 NUL 的 UTF-8。不满足条件或超出编辑限制的文件提供原样下载，不盲目载入编辑器。
- 数学渲染仍关闭；M0 中的 KaTeX 传递依赖告警与分块体积限制仍存在，见 `M0.md`。
- 容器内直接 HTTPS 与两种架构已验收；尚未进行完整磁盘耗尽/保存中强杀故障矩阵、真实外部 HTTPS 代理和公网安全审计，不宣称已完成 M3。

## 文件操作节点的边界

- 回收站支持同盘和跨盘普通文件/目录，不支持永久清空/到期清理。正常恢复成功后清理该恢复条目；异常退出或清理失败可能留下副本/临时容器，不能自动视为垃圾删除。
- 恢复时原父目录必须仍存在；可先在 Explorer 中重建父目录再重试。不提供任意改路径恢复与后台长任务队列。
- 不一致的隔离原件与完整 payload 会共同保留，拒绝把部分清理后的残缺目录当作完整恢复。此类情况、损坏清单和已恢复但残留的备份，需要管理员检查应用数据目录与保留的隔离名称；M3 继续补恢复演练与文档。
- 故障时清单可能仍为 preparing/incomplete；UI 提供尝试恢复，但不承诺任意磁盘故障都可自动修复。回收站不是版本历史或备份，两个卷仍需备份。
- 大目录要计算完整摘要，跨盘回收需要额外空间和文件 I/O，会暂时阻塞同实例的其他存储操作；尚未完成超大目录、磁盘耗尽和复制中杀进程的完整故障矩阵。
- 外部工具不遵守实例锁时仍存在最后校验与移动/清理之间的窗口，沿用前述边界。工作区内跨挂载移动仍被安全策略拒绝，不静默降级为不安全遍历。

## 节点四：容器交付与整体验收

已提供 `Dockerfile`、`compose.yaml`、现有 HTTPS 代理覆盖文件、不会覆盖已有证书的本地 TLS 初始化脚本，以及可复现的容器验收驱动。详细使用说明见 [`DEPLOY.md`](DEPLOY.md)。Go 可选择直接 TLS 或置于既有 HTTPS 代理后；安全 Cookie 没有因容器而放宽。

- 浏览器图片粘贴通过 ClipboardEvent.files 驱动相同处理路径；原生系统剪贴板、输入法与移动系统键盘仍留待 M3。
- 直接 TLS 使用测试自签名证书，测试浏览器显式忽略测试证书信任错误；健康客户端真正信任并校验该证书，未跳过主机名校验。公网受信任证书及反向代理运维仍由部署者配置。
- 数据故障、备份/恢复、安全/无障碍与性能矩阵仍按 M3 继续，不将 M1 验收等同于全部 V1 交付完成。
