# M3 实施记录（进行中）

## 第一节点：浏览器持久化草稿

正文仍以真实文件为权威。浏览器 IndexedDB `folio-recovery` / `drafts` 保存未获磁盘保存确认的恢复副本，不参与服务器正文读取或搜索。没有改变 Markdown 格式，也没有把实时编辑正文放进 React/Zustand。

### 保存与恢复

- 每个打开的编辑会话有独立随机记录键，同一路径在不同页面的草稿不会互相覆盖。缓存包含路径、完整正文、基准正文与强版本、类型、更新时间及格式版本。每次正文更新均通知独立缓存监听器，包括已经是脏状态时的后续输入。
- 150ms 停顿后，以串行 IndexedDB 事务提交；页面隐藏/离开时尽力刷新。磁盘保存成功后只删除本会话的缓存。缓存事务失败会保留待写队列、显示明确错误，并提供重试和下载入口；不自动清空数据库、淘汰旧稿或静默降级。
- 底栏“恢复稿”读取本工作区其他会话的记录。先比较本机正文与当前磁盘版本，再显式打开或另存。恢复到编辑器一律使用源码模式并暂停自动保存；基准相同也须用户手动保存，基准不同或无法读取时进入冲突。已有标签页不被恢复稿覆盖。
- 也可直接把恢复稿另存到现存目录的新路径；创建使用现有不覆盖接口。先确认新副本或新会话缓存保留成功，再删除原缓存。删除缓存前重新核对完整记录，另一页面更新过的记录会拒绝删除。单独删除恢复记录需要二次确认，不删除磁盘或其他会话记录。
- 同一命名空间的未知格式记录保留，可下载可序列化的原始 JSON；不会当成有效草稿自动应用。无法序列化的未知结构只显示明确提示，不自动丢弃。

### 工作区与认证边界

登录和 me 响应新增不暴露路径的 `workspaceId`：由持久化账号初始化盐和安全打开的根目录设备/inode 身份派生。重启同一挂载与 app-data 时稳定；切换目录或应用数据时隔离浏览器记录。它只是恢复命名空间，不是身份凭证或内容 ETag。

浏览器固定页面首次认证的工作区身份，API 请求携带 `X-Folio-Workspace`，预览/下载链接携带同义 `workspace` 查询字段。携带的身份不匹配时，认证中间件在文件操作前返回 409 `workspace_changed`。页面停止自动保存，提供旧内存正文下载与重新加载入口，不把旧会话继续用于新目录。原有客户端未携带此字段时仍沿用原 API 合约；认证、CSRF、ETag 与根目录隔离要求不变。

恢复 UI 只在认证后显示当前命名空间记录。缓存不加密，不能防止拥有浏览器配置目录访问权或同源脚本权限的人读取。应使用私有浏览器配置，尤其是编辑密码和配置文件时。退出登录不会擅自清除尚待用户处理的恢复记录。

### 明确限制

- 缓存提交前的短窗口、浏览器/系统崩溃、存储配额、浏览器主动驱逐数据和清除站点数据都可能使恢复副本不可用。写入期间底栏显示待提交，失败明确提示；离开时仍保留未保存警告，不以本地缓存代替磁盘保存和备份。
- 隐私模式、不同浏览器/设备或不同站点 origin 不共享缓存；HTTPS/HTTP、域名和端口变化也不同。未通过认证时不提供离线文件工作区。
- 复制/恢复挂载导致设备/inode 改变，或重建账号/app-data 后，旧命名空间不会自动绑定到新根。迁移前先保存或下载浏览器草稿；服务器双卷备份不包含各台浏览器的缓存。根 inode 被回收复用时命名空间不是独立安全保证；恢复仍需显式比较，且保存仍使用内容 ETag。
- 恢复的是正文，不包括撤销历史、光标位置和未完成上传的原始附件。已经成功上传的文件仍可从目录核查；标准相对链接随正文缓存。
- 本节点实现页面刷新和实际浏览器重启恢复，不宣称已完成整个 M3。移动端抽屉/触控、双卷备份恢复演练、安全/无障碍审查和实际性能测量仍待实施。
