# M0 实现与验证记录

2026-10-15。此阶段为可行性验证，不是日常可用版本。

## 已实现

- `frontend/`：React + TypeScript + Vite；Tailwind 语义主题、轻量文件列表、两份示例标签页、富文本/源码切换。界面默认中文，主题跟随系统并可手动切换。
- `frontend/src/editors/`：动态加载 Milkdown Crepe 7.22.3 与 CodeMirror 6。按独立宿主挂载/销毁编辑器；同步捕获 Markdown 事务，避免库的防抖事件在切换时丢掉最后输入。
- `frontend/src/sessions/`：正文独立于 React/Zustand，文件和模式切换保留正文与 dirty 状态。Zustand 只管理导航和界面偏好。
- `backend/`：Go `net/http` 服务，健康接口、安全响应头和嵌入式前端。未实现文件接口、认证或数据库。
- 草稿下载、离开页面时的未保存保护、明确的内存状态提示。下载不等于已保存，dirty 状态不会被清除。

## Markdown 转换保护

进入富文本模式时，在不可见宿主中实际执行 Crepe 解析和序列化。除单个末尾换行外，出现任何差异均保留原始字节对应的字符串并返回源码模式。既拒绝丢失，也保守拒绝单纯格式规范化；不会悄悄采用规范化后的结果。

真实浏览器夹具及输入/输出快照在 `frontend/tests/fixtures/markdown.json`、`frontend/tests/browser/workbench.spec.ts-snapshots/`。当前 14 组样本结果：

| 样本 | 观察与处理 |
| --- | --- |
| 中文标题、强调、行内代码 | 往返一致 |
| 相对链接与图片 | 路径往返一致；M0 不提供真实文件加载或导航 |
| 带语言的代码围栏 | 往返一致 |
| Unicode、组合字符 | 往返一致 |
| 嵌套任务列表 | `-` 被转换为 `*`，使用源码 |
| 表格 | 分隔行发生规范化，使用源码 |
| frontmatter | 被解析为普通 Markdown，使用源码 |
| 转义 | 转义形式发生变化，使用源码 |
| 引用式链接 | 被展开为行内链接，使用源码 |
| 多余空行、硬换行 | 空白发生变化，使用源码 |
| HTML 与 HTML 注释 | 样本原文往返一致；不承诺 HTML 交互或预览 |
| 数学公式 | 已禁用公式功能，样本按普通源码保留；不提供公式渲染 |
| 脚注 | 样本源码保留，不承诺完整脚注编辑语义 |

以上只代表已测样本，不是对任意 Markdown 的无损保证。后续升级依赖必须复核快照。富文本编辑过程中由用户操作产生的标准 Markdown 会正常序列化。

## 已知限制与风险

- **没有磁盘保存**。刷新、关闭或进程退出会丢失内存草稿；请先下载。浏览器离开确认受浏览器策略限制，不能替代恢复机制。
- 切换文件、模式后正文保留，撤销历史和光标位置会重置。正式会话历史保留尚未实现，已在界面说明。
- M0 不生成临时 blob 图片链接。图片粘贴/拖放由上传插件明确提示不支持；M1 接入真实上传后再开启。
- 中文文件名和内容已覆盖，原生输入法组合输入、屏幕阅读器及移动端系统键盘尚未完整验收。
- 未提供关闭标签页、CRUD、认证、ETag 条件写入、恢复缓存、搜索、Docker 或真实文件预览。切勿把此版本当作已完成的 M1。
- Go 默认只监听 `127.0.0.1:8080`，尚未通过公网部署安全验收。
- `npm audit --omit=dev` 报告 4 个 low 条目，实际为同一条 KaTeX 传递依赖链（`remark-math → micromark-extension-math → katex`）。M0 禁用 LaTeX，未采用会降级 Crepe 的自动修复；启用数学功能前需解决并复验。
- Crepe 主动态分块仍超过 Vite 默认 500 kB 提示阈值；M0 记录现状，未通过调高阈值掩盖。未设置无依据的性能指标。
- 系统字体用于 UI 与正文；未引入字体文件。只按需引用启用的 Crepe 样式，未引入公式字体。

## 验证方法

```sh
make install
make build
make test
```

`make test` 包括前端静态检查、会话单元测试、7 个浏览器场景和 Go 路由测试。浏览器场景覆盖 14 组 Markdown 快照、快速切换、异步挂载清理、有损转换保护与草稿下载，以及 1440×900、1024×768、390×844 下的明暗主题、无整页横向溢出、说明弹窗焦点恢复。

浏览器测试默认使用 `/usr/bin/google-chrome`，可用 `CHROME_BIN` 指定兼容 Chromium 的实际路径。截图输出到忽略的 `frontend/test-results/`。浏览器数量检查只验证当前挂载状态与跨文件行为，不等于长期堆内存泄漏分析。

生产构建还需通过 Go 服务实际打开页面，检查编辑器懒加载、健康接口及响应头。M1 的路径安全、并发保存、认证等测试在相关功能实现时增加。
